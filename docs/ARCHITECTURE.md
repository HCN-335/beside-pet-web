# 프론트엔드 ARCHITECTURE — Beside Pet (Next.js)

> 클라이언트 설계. 백엔드 맥락은 [../02-architecture.md](../02-architecture.md), 대화 흐름 목업은 [BesidePet_demo.html](BesidePet_demo.html).

---

## 1. 프론트의 역할 (그리고 하지 않는 일)

> **프론트는 "얇다(thin)".** 화면·입력·진행도 표시만 한다.

| 한다 | 하지 않는다 |
|------|-------------|
| 채팅 UI 렌더링, 입력 전송 | 상담 흐름 판단 ❌ |
| 진행도(과제·진행률) 표시 | 다음 질문 결정 ❌ |
| 세션 시작/이어가기 | LLM 직접 호출 ❌ |
| 위기 자원 안내 표시 | **API 키 보관 ❌ (절대)** |

상담 로직·상태·모델은 전부 백엔드 뒤에 있다. 프론트는 *"텍스트를 보내면 발화 + 진행 상태가 돌아온다"*만 안다. → 클라이언트를 얇게 유지해 상담 로직의 단일 진실을 서버에 둔다.

## 2. 왜 Next.js + React (웹)인가

- **데모·리뷰가 쉽다** — URL 하나로 흐름을 보여줄 수 있다 (모바일 빌드/스토어 불필요).
- **백엔드 REST와 깔끔히 분리** — 프론트는 두 엔드포인트만 호출.
- 목표가 "상담 흐름이 진짜로 도는 것"을 *보여주는* 것이므로, 가벼운 웹 클라이언트가 적합하다.

## 3. 화면 흐름

```
 [랜딩/소개] → [온보딩] → [상담 세션(채팅)] → [세션 클로저] → (다음 세션)
                  │             │                    │
                  │             ├ 진행도 바           └ 요약·추모 ritual·다음 예고
                  │             ├ 봇/유저 말풍선
                  └ 검증·동의·안전 스크린·경로 분기(급성/예기)
```

- **온보딩** — 검증 먼저, 문진표 ❌, 모든 질문 건너뛰기 허용. 급성/예기 경로를 결정해 `griefPath`로 세션 시작에 전달.
- **상담 세션** — 핵심 화면. 말풍선 + **상단 진행도 바**(현재 과제 라벨 / 진행률 %). 데모의 `stageLabel·stageFill·stagePct`가 이에 해당.
- **세션 클로저** — 요약·추모 ritual·다음 세션 예고.

## 4. 백엔드 연동 (계약)

프론트가 호출하는 엔드포인트는 **두 개뿐**이다.

| 동작 | 호출 | 받는 것 |
|------|------|---------|
| 세션 시작 | `POST /sessions` `{ sessionId, griefPath, seed? }` | 초기 봇 발화 + 진행 상태 |
| 턴 전송 | `POST /sessions/:id/messages` `{ text }` | 봇 발화 + 갱신된 진행 상태 |

- 응답의 진행 상태(`currentTask`, `overallProgress`)로 진행도 바를 갱신한다.
- 스트리밍 발화가 필요하면 SSE로 확장(향후). 1차 슬라이스는 단순 요청/응답으로 충분.

## 5. 상태 관리 (클라이언트)

- **서버 상태가 진실** — 상담 진행은 백엔드 `GraphState`가 단일 진실. 프론트는 마지막 응답을 *캐싱·표시*할 뿐 자체 상담 상태를 만들지 않는다.
- 데이터 패칭/캐싱: React Query(또는 SWR) 수준이면 충분. 전역 상태 라이브러리는 1차 슬라이스에 불필요.
- 로컬 UI 상태(입력값, 스크롤, 로딩)만 컴포넌트가 들고 있는다.

## 6. 디렉터리 구상 (구현 시)

```
frontend/
├─ app/
│  ├─ page.tsx                 # 랜딩
│  ├─ onboarding/              # 검증·동의·경로 분기
│  └─ session/[id]/            # 채팅 + 진행도 바 + 클로저
├─ components/
│  ├─ chat/                    # 말풍선·입력 dock·스크롤
│  └─ progress/                # 과제·진행률 표시
├─ lib/
│  └─ api.ts                   # /sessions 두 엔드포인트 래퍼 (키 없음)
└─ ...
```

## 7. 접근성·톤 (제품 제약 반영)

- **"정서적 지지" 워딩** — "치료/진단" 표현 회피 (제품 정책).
- 위기 자원(핫라인 등) 표시는 **항상 노출·무료**. 결제·구독 뒤에 숨기지 않는다.
- 슬픔을 다루는 화면이므로 색·모션은 차분하게. 강한 알림/뱃지/게이미피케이션 지양.

## 8. 스코프

- ✅ 1차: 온보딩(급성) → 세션 1(과제 1) → 진행도 표시 → 클로저, REST 연동.
- 🚧 향후: SSE 스트리밍, 예기 경로 화면, 과제 2~4, 세션 이력/회상 UI.
- 현재 [BesidePet_demo.html](BesidePet_demo.html)은 하드코딩 스크립트 목업 — 이 흐름을 위 구조로 옮기고 백엔드에 실연결한다.
