# Beside Pet — Frontend

펫로스 정서 지지 에이전트의 **웹 클라이언트** (Next.js App Router + React).
대화 흐름 판단은 전부 백엔드(beside-pet-api)에 있고, 프론트는 화면·입력·진행도 표시만 담당하는 **얇은 클라이언트**다.

---

## 역할 (그리고 하지 않는 일)

| 한다 | 하지 않는다 |
|------|-------------|
| 채팅 UI 렌더링, 입력 전송, SSE 수신 | 대화 흐름 판단 ❌ |
| 진행도(단계·진행률) 표시 | 다음 질문 결정 ❌ |
| 세션 시작/이어가기, 온보딩 수집 | LLM 직접 호출 ❌ |
| 위기 자원 안내 표시 | **API 키 보관 ❌ (절대)** |

대화의 단일 진실은 백엔드 세션 상태다. 프론트는 응답(`TurnResult`)을 표시할 뿐 자체 대화 상태를 만들지 않는다.

## 화면 흐름

```
[로그인/최초 설정/계정 신청] → 역할 분기
   ├ admin  → [계정 관리 (발급·신청 승인·만료)]
   └ viewer → [세션 허브(/sessions)] ─ 이어하기 / 새 대화(여정 재개) → [세션(채팅+진행도)] → [클로저]
                 ├ 전사 다시보기 (/sessions/[id])          └ 위기 시: 안전 자원 안내
                 ├ 마음 리포트 (/sessions/[id]/report)
                 └ 설정 (/settings — 대화·앱 언어)
       첫 방문만: [온보딩(스크립트 인테이크)] → 세션
```

- **온보딩**은 LLM 없이 결정론적 스크립트 대화로 프로필(이름·함께한 기간·이별 경로 등)을 수집해 세션 시드로 넘긴다 — 최초 1회만.
- **새 대화는 여정을 이어간다**: 프로필을 상속하고 지난 도달 단계에서 재개하며, 동반자가 지난 대화의 맥락을 이어받아 인사한다.
- **최초 설정**: 백엔드에 관리자가 없으면 로그인 대신 설정 폼이 뜬다(부팅 로그의 1회용 토큰 사용). 계정 신청은 관리자 승인 후 로그인 가능.

## 아키텍처 — Feature-Sliced

기능 우선 수직 슬라이스, 레이어는 얇게. 추상화(포트)는 API 경계 한 곳에만 둔다.

```
frontend/
├─ app/                  # 라우트는 조립만 (/, /onboarding, /session, /sessions, /admin)
├─ features/             # auth · onboarding · session · session-archive · safety · admin
│  └─ <feature>/{components, *.store.ts, *.types.ts}
├─ components/chat/      # 온보딩·세션 공용 채팅 UI (말풍선·리스트·컴포저)
├─ lib/
│  ├─ api/               # 유일한 백엔드 포트 (mock ↔ http 스위칭)
│  ├─ http/              # 공용 HTTP 클라이언트 (base URL·쿠키·에러를 한 곳에서)
│  ├─ data/              # 읽기 게이트웨이 (store는 여기만 호출)
│  ├─ cache/             # 타입드 TTL 캐시 팩토리
│  └─ stream/            # SSE 수신
└─ i18n/                 # ko/en 카탈로그 + 쿠키 로케일
```

**상태 규칙**: feature당 Zustand store 1개, use case 1개 = store action 1개. 컴포넌트는 표현만, selector로 구독.

## 백엔드 연동

`lib/api`가 유일한 창구 — 환경변수로 mock ↔ 실서버를 스위칭하므로 백엔드 없이도 전체 플로우가 돈다.

```bash
pnpm install
pnpm dev                          # mock 모드 — 백엔드 없이 동작
# .env.local: NEXT_PUBLIC_USE_BACKEND=1 → beside-pet-api 실연동 (JWT httpOnly 쿠키)
```

## 톤·접근성 (제품 제약)

- **"정서적 지지" 워딩** — 치료·진단 표현을 쓰지 않는다.
- 위기 자원 안내는 **항상 노출·무료** — 어떤 흐름 뒤에도 숨기지 않는다.
- 차분한 색·모션. 강한 알림/게이미피케이션 지양.

## 로드맵

### Phase 1 — 뷰어 경험 (마무리 단계)

완료:

- [x] 로그인 게이트·역할 분기 · 최초 설정 폼 · 계정 신청 플로우 (승인제)
- [x] 스크립트 온보딩 인테이크 (LLM 없이 결정론, 최초 1회)
- [x] 스트리밍 채팅 — 타이프라이터 페이싱 · 멀티라인 컴포저(500자 카운터)
- [x] 세션 허브 — 목록(시작 시각·삭제) · 전사 다시보기 · 마음 리포트(가용 게이트 반영) · 이어하기/새 대화(여정 재개)
- [x] 채팅에서 나가기·대화 마치기 — 둘 다 목록으로 복귀
- [x] 설정 페이지 (대화 언어 · 앱 언어 · 로그아웃) · 위기 자원 안내
- [x] admin 콘솔 — 발급 · 신청 승인 · 정지 · 만료 · 복구 (i18n 포함)
- [x] mock ↔ 실서버 이중 포트 (`lib/api`) + 공용 HTTP 클라이언트 · 데이터 게이트웨이 · TTL 캐시
- [x] i18n ko/en — 쿠키 로케일, 서버 첫 페인트 반영, 단계명·리포트 제목까지 클라이언트가 라벨링

남은 작업:

- [ ] 세션 목록 다듬기 (대화 언어 배지 등)

### Phase 2 — 운영 대시보드·품질

- 세션 목록 페이지네이션 — 1·2·3… 페이지 번호로 넘기는 방식. 백엔드가 `page`/`size`와 전체 건수를 주면 그 위에 얹는다
- admin 대시보드 — 위기 세션 모니터링, 완주율·위기율·비용 인사이트 카드 (백엔드 집계 + Langfuse 지표 연동)
- Supervisor 플래그 검토 큐 UI
- 접근성·모바일 다듬기, 세션 이력 고도화
- AI 주도 검증 자동화 — 백엔드 로드맵 Phase 3과 통합 추진 (고정 테스트 코드 없이 에이전트 주행)

> 배포·인프라 계획은 백엔드 저장소(beside-pet-api)의 로드맵에서 통합 관리한다.
